# 模块审查技能（module-review）

自动定位：读档案（注入检查项）→ 读总契约（索引）→ 读 `{文档根}/模块/{模块名}/` 四件套（契约/接口/测试/脚本）→ 对照代码检查。

> **DSH 触发**：显式触发词为 `/module-review {模块名}`（中文命令 `/检查` 为方法论约定，DSH 只识别英文技能名）。

## 检查清单

### 一、通用清单（任何技术栈都查）

| # | 检查项 | 违规级别 |
|---|--------|---------|
| 1 | 契约↔代码文件一致性（契约声明的表/字段/状态机与代码、SQL 一致） | HIGH |
| 2 | 接口.md 与契约 §4 概览一致（接口清单与权限标识对齐） | HIGH |
| 3 | 导航区完整（四件套互链、关联文档存在、标杆代码路径有效） | MEDIUM |
| 4 | **回写查账**（校验 /代码 的回写义务已履行：契约变更记录有登记、接口.md 与代码一致、总契约索引已更新） | 漏写即 HIGH |
| 5 | 软删除 / 乐观锁实现（按档案通用约定） | HIGH |
| 6 | SQL 参数化（无 `${}` 拼接用户输入） | CRITICAL |
| 7 | 无硬编码密钥/密码/Token | CRITICAL |
| 8 | 输入校验（新增/修改接口参数有校验） | MEDIUM |
| 9 | 依赖注入存在性（注入的 Service/接口确实存在） | CRITICAL |

### 二、档案注入清单（从档案"技术栈特有检查项"读取）

按项目档案登记的检查项执行（如"继承统一 Controller 基类""接口级权限注解全覆盖""按钮权限指令控制"等），仅对应技术栈项目才检查。

## 输出格式

```
## {模块名} 代码审查报告

### CRITICAL（必须修复）
| # | 检查项 | 文件 | 问题描述 |

### HIGH（强烈建议修复）
| # | 检查项 | 文件 | 问题描述 |

### MEDIUM（建议修复）
| # | 检查项 | 文件 | 问题描述 |

### LOW（可选修复）
| # | 检查项 | 文件 | 问题描述 |

### 检查统计
- 总检查项: N / 通过: N / CRITICAL: N / HIGH: N / MEDIUM: N / LOW: N
```

全部检查完成后，如果 CRITICAL 和 HIGH 均为 0，提示用户可提交；否则列出问题并建议 `/文档 {模块名} 同步` 或 `/代码 {模块名}` 修复。
