# 模块测试技能（module-test）

负责 `测试/` 下除 `验收.md` 之外的测试资产：

```text
测试/
├── 验收.md          ← /module-doc 维护；本技能只读
├── 方案.md          ← 本技能维护（策略 + 索引）
├── {主题}_测试.md   ← 本技能维护（可执行测试文档）
├── test.sh          ← 本技能维护（可选）
└── 报告/            ← 本技能写（每次执行）
```

> **`验收.md` 不是本技能写的**：`SC-{模块名}-NN` 的唯一事实源在 `测试/验收.md`，由 `/module-doc` 建档/合并时维护。本技能只读，**不得改写、重排或删除**。
> **只有 `_测试.md` 是可执行测试文档**；`验收.md`、`方案.md`、`test.sh` 都不是“执行入口”。
> **测试执行可选**：没有 `方案.md`/`_测试.md`/`test.sh` 的模块可以只有 `验收.md`。

## 0. 前置条件

```
/module-test 所有形态的前提：
  ✅ 模块契约.md 存在（§4 接口 / §5 落点 / §7 不变量）
  ✅ 模块接口.md 存在
  ✅ 测试/验收.md 存在（SC 索引 + Scenario 正文）
  ❌ 验收缺失 → 停，提示“先跑 /module-doc {模块名} 补 测试/验收.md”
```

**迁移期兼容（schema2）**：旧契约 10 章、SC 在契约 §8.2、模块根还是 `测试.md`。此时可临时读契约 §8.2，但必须提示：
> `ℹ️ 本模块仍是 schema2：旧测试资产。请先按 migrate v5 迁到 测试/验收.md + 测试/方案.md + _测试.md。`

## 1. 三个入口

| 命令 | 作用 |
|---|---|
| `/module-test {模块名}` | 生成/更新 `测试/方案.md`、`测试/{主题}_测试.md`、`测试/test.sh`（草稿/讨论，不执行全部） |
| `/module-test 测试/{主题}_测试.md` | **单主题执行**：路径即启动词，不再加“执行”/`--run` |
| `/module-test 测试/方案.md` | **全量执行**：按方案 §6 主题索引依次跑全部 `_测试.md` |

兼容别名：`/module-test {模块名} 执行`、`/module-test {模块名} --run` 等价于 `测试/方案.md`；仅迁移期保留。

**拒绝入口**：

- `/module-test 测试/验收.md` → 验收只读，不是执行入口；
- `/module-test 测试/test.sh` → 脚本不是入口，由 `_测试.md`/`方案.md` 调用；
- 未登记的 `_测试.md` → 先更新 `方案.md §6`，不直接执行。

## 2. 场景一：生成/讨论定稿

```text
/module-test {模块名}
```

**步骤**：

1. 读 `测试/验收.md`
   - SC 索引表 + `#### Scenario:` 正文；
   - 记录每个 SC 的 ID 与短名；后续只引用 ID，不复制正文。

2. 读契约与接口
   - 契约 §4 接口清单 → 黑盒用例骨架；
   - §3 数据模型 / §3.2 状态机 → 白盒断言；
   - §5 应用落点 → 端层/编排层是否适用；
   - §7 不变量 → 断言边界（不要把 INV 复述成新 SC）；
   - `接口.md` → 路径/方法/参数/字段。

3. 读 `测试规范.md`
   - §1.1 适用层判定：接口层必备；库层有持久化状态时；端层有前端落点；编排层 ≥2 个服务端应用。

4. 生成/更新 `测试/方案.md`（按模板 §1–§9）：
   - §1 测试目标；§2 适用层；§3 前置；§4 账号；
   - §5 验收场景与用例对应（只引用 `验收.md` 的 SC ID）；
   - §6 主题索引（主题 / `{主题}_测试.md` / 覆盖 SC / 执行方式）；
   - §7 执行方式（单主题 / 全量 / 生成）；
   - §8 报告约定（单主题 / 全量命名与保留）；
   - §9 验证 SQL 取值（骨架见 测试规范 §4）。

5. 生成/更新 `测试/{主题}_测试.md`：
   - 如 `接口层_测试.md`、`端层_测试.md`、`分发通道_测试.md`；
   - 固定 `## 1. 用例` 表；
   - 只写步骤与步骤级取证点，不复制 `验收.md` 的 WHEN/THEN；
   - 每个主题文件必须登记在 `方案.md §6`，不允许孤儿。

6. 生成/更新 `测试/test.sh`（可选）：
   - 从接口层用例生成 curl 步骤；
   - 参数化 BASE_URL；PASS/FAIL 计数；
   - 不含删除/清理逻辑；模板默认覆盖接口层，其他主题按 `_测试.md` 执行（不伪造脚本覆盖）。

7. 展示给人 → 讨论修改 → 定稿；跑 `check`，确认 `test-content` 不报错。

**生成时不执行全部用例**；执行走 §3。

## 3. 场景二：执行

### 3.1 单主题执行

```text
/module-test 测试/接口层_测试.md
```

1. **入口校验**：
   - 文件名必须是 `_测试.md`；
   - 必须被 `测试/方案.md §6` 索引；
   - 引用的 SC 必须存在于 `测试/验收.md`；
   - 不通过 → 停，报差异清单。
2. **执行**：
   - 有 `test.sh`：执行 `bash 测试/test.sh`（模板默认覆盖接口层；`--topic 接口层`/`TOPIC=接口层` 等价；其他主题脚本模板不覆盖，按 `_测试.md` 执行）；
   - 无 `test.sh`：按 `_测试.md` 的用例逐条执行，记录 PASS/FAIL/SKIP，不伪造 PASS。
3. **写报告**：
   - `测试/报告/v{YYYY-MM-DD}-{短SHA}-{主题}.md`；
   - 基线取 `契约.md` / `接口.md` / `测试/验收.md` 最后提交的较晚者；
   - 任一文件有未提交改动或无 git → 降级 `v{YYYY-MM-DD}-nogit-{主题}.md`（`nogit` 是固定降级标记，不是短 SHA）。
4. **输出**：PASS/FAIL 汇总 + 每条失败详情 + 建议通道；不自动修代码。

### 3.2 全量执行

```text
/module-test 测试/方案.md
```

1. 读 `方案.md §6` 主题索引，按顺序执行全部 `_测试.md`；
2. 每个主题按 §3.1 的单主题规则执行；
3. 写汇总报告：`测试/报告/v{YYYY-MM-DD}-{短SHA}-全量.md`（含各主题 PASS/FAIL 与失败明细）；
4. 单主题报告可同时保留；同一基线 + 同一主题覆盖同名报告。

### 3.3 报告格式

```markdown
# {模块名} 测试报告 v{YYYY-MM-DD}-{短SHA}-{主题|全量}

> 执行时间：{YYYY-MM-DD HH:mm}
> 契约版本：v{YYYY-MM-DD}-{短SHA}（基线提交 {短SHA}）
> 执行入口：测试/{主题}_测试.md / 测试/方案.md
> 执行方式：test.sh / 手工

## 结果概要

PASS={n}  FAIL={n}  SKIP={n}

## 失败详情

### F-1 {失败用例名}
- **期望**：{期望值}
- **实际**：{实际值}
- **根因推测**：{分析}
- **建议通道**：{/module-code 或 /module-plan}
- **理由**：{简短理由}

## 环境

- BASE_URL_SVC_MAIN: http://{实际值}
- 测试账号：{账号名}
```

报告默认保留最近 10 份；是否入库由项目决定。报告不写 `docstruct` 哨兵，不参与 `check`。

## 4. 一致性校验（执行前必做）

- `测试/验收.md` 的索引表与 `#### Scenario:` 正文 1:1，ID 唯一且 `SC-{模块名}-NN`；
- `测试/方案.md §5` 引用的 SC 都存在；
- `验收.md` 的每个 SC 都在 `方案.md`/主题里有用例；
- `方案.md §6` 的主题索引 ↔ `_测试.md` 文件一致，无孤儿、无缺失；
- `_测试.md` 不复制 `验收.md` 的 WHEN/THEN，不写执行记录/缺陷史；
- 旧 `SC-1`、`§7-n` 引用 → 停，先迁移；
- 不一致 → 报差异清单：SC 问题转 `/module-doc`，用例问题留在本技能修。

```text
├── 接口.md              ← 不动
├── 测试/

│   ├── 方案.md          ← 本技能
│   ├── 接口层_测试.md   ← 本技能
│   ├── 端层_测试.md     ← 本技能（按需）
│   ├── 分发通道_测试.md ← 本技能（按需）
│   ├── test.sh          ← 本技能（可选）
│   └── 报告/
│       ├── v2026-10-21-abc1234-接口层.md
│       └── v2026-10-21-abc1234-全量.md
└── 计划/
```

## 6. 不做什么

- **不创建/更新契约**（归 `/module-doc`）
- **不创建/更新接口文档**（归 `/module-doc`）
- **不创建/改写 `测试/验收.md`**（归 `/module-doc`；SC 变化必须回 `/module-doc`）
- **不修改代码**（归 `/module-code`）
- **不创建/修订计划**（归 `/module-plan`）
- **不在测试文档里追加执行记录/缺陷史/历史沿革**（→ `测试/报告/`、`探索/`、git）
- **不新增模板之外的一级章节**
- **不自动跳转修复通道**（输出建议，等人决定）
