# 模块文档技能（module-doc）

负责模块四件套（契约 / 接口 / 测试 / 脚本）的**创建与更新**。分工：**文档归 /module-doc、代码归 /module-code**，/module-review 兜底一致性；**探索与讨论归 /module-explore**（模块还没确定时先探索）。

> **触发**：`/module-doc {模块名}`。**零后缀、零参数**——模式由 AI 探测后带编号请你确认；强制模式回编号或用自然语言。

## 0. 上下文自动发现（零路径投喂 + 应用路由）

1. 读项目档案——**先读「应用清单」（路由表）**：应用 → 类型/代码根/规范文件/数据库/依赖；再读文档根、语言、通用约定、标杆映射、文档导航；
2. 读总契约——模块索引表、依赖矩阵、应用拓扑；
3. **应用路由**：确定本模块涉及的应用（已有模块读契约 §5 落点表；新模块按需求推断，推断不出**只问一次**主责服务与涉及端）；
4. 涉及跨模块/跨服务能力时读对应边界文档（缺索引则扫 `{文档根}/边界/`）；
5. 发现档案缺登记时**提示回填档案**，而非反问用户要路径。

## 1. 三种模式（按"真相来源"分）

| 模式 | 真相来源 | 产出与停止点 |
|------|----------|--------------|
| **A 需求驱动** | 需求 | 生成/更新**契约**（可停在契约、多轮迭代）；需求已稳时才继续出接口 |
| **B 代码对账** | 代码 | **分组差异清单** → 分组确认 → 回写**契约 + 接口**（§9 标注来源=代码） |
| **C 产物补齐** | 契约 | 前置检查通过后，按序产出**接口 → 测试 → test.sh**；测试依据 `测试规范.md` |

### 1.1 判定：意图优先，状态校验（不可跳）

```
第 1 步：读用户意图（从话里取，不从状态猜）
   需求词（§1.4 词表）        → 候选 A
   代码既成语（§1.4 词表）    → 候选 B
   补产物词（§1.4 词表）      → 候选 C
   无意图词                  → 进入第 2 步由状态推断

第 2 步：用仓库状态校验候选
   无契约 + 有代码 + 需求词   → 【B→A 复合流程】（§5，最高频）
   无契约 + 有代码（无需求词）→ B（从零生成 契约+接口）
   无契约 + 无代码            → A
   有契约 + 需求词            → A（更新契约+接口）
   有契约 + 代码词            → B（分组差异回写）
   契约与代码一致 + 产物缺失   → C（前置检查见 §4）
   判定"不影响契约语义"        → 【无需文档变更】结论（说明理由，不写 §9）

第 3 步：冲突/低置信 → 只问一个问题二选一；仍不成形 → 重定向 /module-explore
```

**三条反直觉规则**（必须执行）：

1. 用户显式意图 > 状态推断；**不得因为"代码恰好存在"就自动走 B**；
2. B 的触发条件是"用户确认代码是既成事实、不打算改代码"，不是"能读到代码"；
3. **无契约 + 有代码 + 需求词 = 复合流程**（先 B 建基线再 A 叠需求），不是二选一。

### 1.2 确认门（任何模式首写前一律确认；编号 = 强制入口）

**固定格式**（事实 + 模式 + 产物 + 编号备选）：

```
探测事实：契约存在 ✓；代码落点 12 个文件，与契约有差异 → 候选 B 代码对账
将写入：契约 §3/§4 + 接口.md；不生成测试
1) 确认按 B 执行    2) 改为 A（以需求为准）    3) 改为 C（只补产物）
```

- 回复**数字** = 精确切换模式并视为确认（封闭输入，不依赖语义解析）；
- 回复自然语言同样生效；**用户显式指定时 AI 必须遵从**（即使与探测冲突），并记一句"**用户强制指定，覆盖探测**"；
- 执行中命中 §3.2 停条件才再次打断；否则一次确认走完。

### 1.3 探测规则表

| 探测事实 | 模式 |
|----------|------|
| 无契约 + 无代码（或用户只给需求） | A |
| **无契约 + 有代码 + 需求词** | **B → A 复合**（§5） |
| 无契约 + 有代码（无需求词） | B |
| 有契约 + 代码不一致（用户说"代码改了/同步"） | B |
| 有契约 + 用户描述的是需求变更 | A |
| 契约与代码一致，但 接口.md / 测试.md 缺失或不完整 | C |
| 有契约 + 用户明确说"补齐接口/测试" | C |
| 任一模式判定"不影响契约语义"（纯实现/文案/样式） | **无需文档变更**（说明理由后结束）；真要把代码改掉 → 走 `/module-code {模块名}` **直改通道**（免计划，边界=契约 §5 落点） |
| 用户给的是**主题**而非模块名，且需求不成形 | 不猜 → 提示 `/module-explore {主题}` |

### 1.4 词表（冲突判定的可复现依据）

- **需求词**：新增 / 增加 / 改成 / 要支持 / 应该 / 需要（描述期望行为）
- **代码既成语**：代码已经改了 / 线上就是这样 / 现在已经是 / 同步一下（把代码当事实）
- **补产物词**：出接口 / 补接口 / 写测试 / 补测试 / 出方案
- **冲突信号**：同时出现需求词与代码既成语；或状态与意图矛盾；或代码落点含 TODO/空实现标记 → 走"只问一个问题"档。

### 1.5 旧后缀兼容（不宣传，但识别）

`新建`→A（且停在契约）｜`补文档`→B（无契约）｜`同步`→B（有契约，**允许改契约**）｜`改造`→A（需求变更）。旧后缀只作为自然语言提示被识别，不再是正式语法。

## 2. 模式 A：需求驱动（契约先行，可停在契约）

1. 应用路由 → 读标杆、边界、总契约依赖矩阵；
2. 生成**契约草案**（10 章 + 主责服务声明 + §5 应用落点表 + §8.2 验收场景），**默认不生成接口 / 测试**；
3. 与用户**多轮迭代**：每轮改契约 → 汇报改动 → 停；直到用户明确说"契约定了 / 出接口"；
4. **契约定稿信号**：用户说"契约定了"时，在契约 §9 追加一行 `契约定稿（YYYY-MM-DD）`（给 review 一个客观信号）；
5. 契约稳定后（可选）：从 §4 概览产出接口骨架；
6. 回写总契约模块索引表。

- **导航区规则**：停在契约时，导航区**只列已存在的文件**；未生成的写"接口.md（待生成）/ 测试.md（待生成）"——不得写裸链接（否则 review 报断链）；
- **需求变更（改造）同走 A**：更新契约 + 接口.md + §9 变更记录（**来源=需求**）；扩展到新应用先登记 §5 落点（落点先登记后实施）；
- **无需文档变更**：判定不影响契约语义时，说明理由后结束，不硬写变更记录。
  - 若该改动由 `/module-code` 直改通道执行，则**由 /module-code 在 §9 记一行来源=`实现`**（表示"只动实现、未动语义"），本技能不重复记录；
  - **§5 落点表的准确性是直改通道的前提**：直改通道的应用级边界就是从 §5 推导的——落点多了 → 白名单过宽；落点少了 → 直改被误判越界。所以模式 A/B 更新落点表时必须如实完整。

## 3. 模式 B：代码对账（以代码为准回写文档）

> 护栏：**不允许直接覆盖**——先出分组差异清单、分组确认、登记来源。

### 3.1 步骤

1. 按应用清单**逐应用**到其代码根 glob 定位落点代码（`*Controller.java`、`views/*/{模块}/`、`pages/{模块}/`、`pages.json` 等；路径从清单派生，禁止写死目录名）；
2. 读各应用落点代码（Controller / Service / Mapper / 各端页面）；
3. 产出**分组差异清单**：

   | 组 | 内容 | 默认 |
   |----|------|------|
   | **必改** | 接口路径/方法、状态机与枚举 code、权限标识、应用落点 | 建议全接受 |
   | **建议** | 字段名称/类型、必填性、错误码文案 | 逐组确认 |
   | **仅登记** | 字段说明、枚举文案、注释级差异 | 默认只登记不改契约 |

   行格式：`| # | 对账项 | 组 | 契约现值 | 代码事实 | 建议动作 | 置信度 |`

4. **分组确认**（可"只接受必改+建议"）；"需人工确认"项不得默认采纳；
5. 回写范围 = 确认差异项影响的**全部下游文档**：契约（§3/§4/§5）+ **接口.md 对应字段** + 落点表；契约 §9 追加记录并**标注来源=代码**；
6. 回写总契约索引。

### 3.2 停条件（命中立即停，不硬走完）

| 命中反例 | 动作 |
|----------|------|
| 差异成因是"需求本来就没实现"（代码缺功能），而非"代码偏离契约" | 停 → 转 A（需求驱动），不得把缺失当差异回写 |
| **应用之间不一致**（如 web 端与移动端状态语义不同） | 停 → 只报差异，提示走 `/module-plan` 修代码；**不得把某一端写进契约** |
| 用户显式指定了另一模式 | 以用户为准，记录覆盖原因 |

## 4. 模式 C：产物补齐（契约 → 接口 → 测试）

> 前提：契约与代码一致。**前置一致性检查必须逐项执行并报告结果**：

| # | 检查 | 通过标准 |
|---|------|----------|
| 1 | §5 应用落点文件存在 | 每个落点路径可 stat 到 |
| 2 | §4.2 接口路径可在代码中找到 | 逐个在对应服务代码中命中（路由/注解/方法名） |
| 3 | §3.2 枚举 code 与代码一致 | 状态/结果枚举 code 集合一致 |
| 4 | 接口.md 中标 ❌ 未接入的端 | **不算不一致**（是 backlog，不阻塞 C） |

任一（1–3）不通过 → **停**，建议先走 B。

**步骤**：读契约（§3/§4/§5/§8.1/§8.2）与 `测试规范.md` → **接口.md**（字段级细节 + 服务归属/类型/消费方 + §5 接入状态）→ **测试.md**（先写「适用层与依据」，再写用例，断言引用 SC-n）→ **test.sh**（由 `templates/scripts/e2e_template.sh` 复制改造，参数化多 `BASE_URL`）→ 回写契约 §8 引用与测试执行记录。

## 5. 复合流程 B → A（无契约 + 有代码 + 带需求）

```
1. B 建基线：分组差异清单（从零）→ 确认 → 生成契约 + 接口（§9 记"来源=代码"）
2. 基线确认：向用户展示基线契约要点，确认无误
3. A 叠需求：在基线上更新契约 §3/§4/§5 + 接口.md（§9 记"来源=需求"）
4. 回写总契约索引
```

**停止点**：B 基线未经确认，不进入 A；A 阶段默认仍停在契约（除非用户要出接口/测试）。

## 6. 生成文档的硬性要求

1. **导航区**：头部包含导航区（自动填值）：
   ```markdown
   > 关联文档：总契约.md、边界/{能力}边界.md、规范/应用-{涉及应用标识}.md
   > 关联代码：{标杆模块} → {代码路径}
   > 回链：本模块 接口.md / 测试.md（未生成时标"（待生成）"）
   ```
2. **契约 §4 与接口.md 分工（防双维护）**：契约 §4 只保留"接口概览表 + 权限校验规则 + 接口对状态的影响"；字段级细节一律以 `接口.md` 为唯一事实源；端差异写在应用规范或契约 §5"差异说明"列；
3. **探索记录回链（如存在）**：契约导航区加"设计由来：探索记录路径"——只回链不复制（论证只留一处）；
4. **验收场景化（§8）**：§8.1 验收标准清单（标注对应场景编号）+ **§8.2 关键验收场景用 Scenario 写法**（`#### Scenario: SC-n` + WHEN/THEN，THEN 写可观测结果）；测试.md 用例与 test.sh 按场景实现；
5. **绘图规范**：依赖图（§2）、状态机（§3）、页面结构（§5）一律 mermaid，禁止 ASCII；页面结构每端一张，端多折叠为链接；
6. **文件名**：按档案"文档语言"映射——**语言由文档根目录名识别**（中文 `doc-framework/`、英文 `doc-framework-en/`），且解析器按节名关键词定位，必须与映射表一致：
   - 中文：`{文档根}/模块/{模块名}/{契约.md,接口.md,测试.md,test.sh}`，档案 `项目档案.md` 的 `## 应用清单`，契约 `## 5. 应用落点`；
   - 英文：`{文档根}/modules/{module}/{contract.md,api.md,testing.md,test.sh}`，档案 `profile.md` 的 `## App registry`，契约 `## 5. Application footprint`；
   - 内部命名**要么全中文、要么全英文，禁止混用**（完整映射见框架 README「文档语言与命名」）；
7. **§9 来源标注**：契约 §9 每条**新增**记录标注来源——`需求`（模式 A）/ `代码`（模式 B）/ `实现`（/module-code 直改通道的免计划小改，"未动语义"）；
8. **回写**：创建/更新后回写总契约模块索引表（模块名、主责服务、各应用落点、标杆参考、边界依赖）。

## 7. 完成

输出：模式与判定依据 + 文件清单 + 产物范围（明确"未生成什么"）+ 下一步提示（`/module-plan {模块名}` 或 `/module-review {模块名}`）。
