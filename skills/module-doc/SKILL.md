# 模块文档技能（module-doc）

负责模块四件套（契约 / 接口 / 测试 / 脚本）的**创建 / 逆向提炼 / 更新**。与 /module-code 分工：**文档归文档、代码归代码**，/module-review 兜底校验一致性；**探索与讨论归 /module-explore**（需求模糊/方案未定时先探索，本技能不承担讨论职责）。

> **触发**：显式触发词为 `/module-doc {模块名}`（仅英文技能名触发）。

## 0. 上下文自动发现（零路径投喂 + 应用路由）

不依赖用户提供路径，按以下顺序自动定位（用户主动给的路径作为覆盖优先）：

1. 读项目档案（`{文档根}/项目档案.md`，下同）——**先读「应用清单」（路由表）**：应用 → 类型/代码根/规范文件/数据库/依赖；再读文档根、语言、通用约定、模块形态清单、标杆映射、文档导航；
2. 读总契约——模块索引表、依赖矩阵、应用拓扑；
3. **应用路由**：确定本模块涉及的应用集合（已有模块读契约 §5 应用落点表；新模块先按需求关键词推断，推断不出**只问一次**主责服务与涉及端，写入契约后不再问）——后续只加载这些应用的规范（`规范/应用-{应用标识}.md`）与标杆；
4. 涉及跨模块/跨服务能力时读对应边界文档（按档案"文档导航"索引；缺索引则扫 `{文档根}/边界/`）；
5. 发现档案缺登记时**提示回填档案**，而非反问用户要路径。

## 1. 模式判定（自动探测 + 分支确认）

触发后先探测目标模块状态，在分支点**向用户汇报确认**（用户一句话可纠正；也可用命令后缀显式指定跳过探测）：

| 探测事实 | 模式 | 流程 |
|---------|------|------|
| 模块文件夹存在 + 契约.md 存在 | 改造更新 | 按需求更新四件套 → 回写总契约索引 |
| 无文档 + 代码存在（按应用清单到各应用代码根 glob 命中 Controller / views / pages） | 逆向提炼 | 读代码 → 提炼四件套草稿（标注置信度）→ 用户确认 → 回写索引 |
| 均不存在 | 文档先行 | 契约=需求分析：生成契约 + 接口骨架 → 用户确认（实施计划由 /module-plan 生成） |

**显式指定（可选，优先于探测）**：

- `/module-doc {模块名} 补文档` → 强制逆向提炼
- `/module-doc {模块名} 新建` → 强制文档先行
- `/module-doc {模块名} 改造` → 强制改造更新
- `/module-doc {模块名} 同步` → 按代码最新状态同步接口.md / 测试（契约语义变化走"改造"）

缺省走自动探测 + 分支确认。

## 2. 逆向提炼模式要点

1. 按档案应用清单**逐应用到其代码根下 glob** 定位模块代码（`*Controller.java`、`views/*/{模块}/`、`pages/{模块}/`、`pages.json` 等模式，按各应用规范目录约定；**路径从清单派生，禁止写死目录名**）；
2. 读各应用侧的落点代码（Controller / Service / Mapper / 各端页面）；
3. 生成四件套**草稿**，逐项标注置信度：
   - 字段 / 状态机 / 接口 / 服务归属 → "从代码推断"；
   - 权限语义 / 特殊约定 / 应用落点完整性 → "需人工确认"；
4. 用户确认修正后回写总契约索引。

## 3. 文档先行模式流程

1. 读项目档案（应用清单、文档导航、标杆映射）→ 读总契约（依赖矩阵、应用拓扑）；
2. **确定主责服务与涉及应用**（探测候选 → 用户确认，写进契约头与 §5 落点表——**落点先登记后实施**）；
3. 按档案标杆映射读标杆代码（按应用分列；映射缺失时 glob 找同类实现并提示回填档案）；
4. 涉及跨模块/跨服务能力时读对应边界文档；
5. 生成契约（10 章，见模板规格；§5 应用落点表一行一应用；§10 为"生产环境 SQL 执行登记"，按所属服务登记）与接口骨架（接口清单含服务归属/类型/消费方，§5 接入状态初始全空），图按绘图规范用 **mermaid** 绘制；
6. 用户确认（**实施计划由 /module-plan 按契约生成**）。

## 4. 生成文档的硬性要求

1. **导航区**：所有生成文档头部必须包含导航区（自动填值）：
   ```markdown
   > 关联文档：总契约.md、边界/{能力}边界.md、规范/应用-{涉及应用标识}.md
   > 关联代码：{标杆模块} → {代码路径}
   > 回链：本模块 接口.md / 测试.md（四件套互链）
   ```
2. **契约 §4 与接口.md 分工（防双维护）**：契约 §4 只保留"接口概览表 + 权限校验规则 + 接口对状态的影响"；字段级细节一律以 `接口.md` 为唯一事实源（服务端真相）；端差异（字段裁剪/派生）不写进接口.md，写在应用规范或契约 §5"差异说明"列；
3. **探索记录回链（如存在）**：若本模块立项前有探索记录（`{文档根}/探索/YYYY-MM-DD-{主题}.md`），在契约导航区加一行"设计由来：探索记录路径"——只回链不复制（论证只留一处）；需求明显模糊且无探索记录时，提示先 `/module-explore {主题}`，而不是直接猜着写契约；
4. **验收场景化（§8）**：契约 §8.1 保留验收标准清单（表格，标注对应场景编号），**§8.2 关键验收场景必须用 Scenario 写法**（`#### Scenario: SC-n {短名}` + `- **WHEN** …` / `- **THEN** …`），THEN 写可观测结果（库字段/接口响应/待办变化）；场景是断言的唯一真相，测试.md 用例与 test.sh 按场景实现，实施计划 §八引用场景编号；
5. **绘图规范**：依赖图（§2）、状态机（§3）、页面结构（§5）一律 mermaid（flowchart / stateDiagram-v2），禁止 ASCII 图；页面结构每端一张，端多时折叠为链接；
6. **文件名**：按档案"文档语言"映射（中文 `{文档根}/模块/{模块名}/契约.md` / 英文 `docs-framework/modules/{module}/contract.md`）；
7. **回写**：创建/更新模块后**回写总契约模块索引表**（模块名、主责服务、各应用落点、标杆参考、边界依赖）；模块跨越新应用时同步总契约 §三 应用拓扑引用是否仍成立。

## 5. 完成

输出文件清单 + 提示下一步：`/module-code {模块名}`（执行）或 `/module-review {模块名}`（验证）。
