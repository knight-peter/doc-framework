# 模块文档技能（module-doc）

负责模块四件套（契约 / 接口 / 测试 / 脚本）的**创建 / 逆向提炼 / 更新**。与 /module-code 分工：**文档归文档、代码归代码**，/module-review 兜底校验一致性。

> **触发**：显式触发词为 `/module-doc {模块名}`（仅英文技能名触发）。

## 0. 上下文自动发现（零路径投喂）

不依赖用户提供路径，按以下顺序自动定位（用户主动给的路径作为覆盖优先）：

1. 读项目档案（`{文档根}/项目档案.md`，下同）——文档根、语言、目录约定、模块形态清单、标杆映射、文档导航；
2. 读总契约——模块索引表、依赖矩阵；
3. 涉及跨模块能力时读对应边界文档（按档案"文档导航"索引；缺索引则扫 `{文档根}/边界/`）；
4. 发现档案缺登记时**提示回填档案**，而非反问用户要路径。

## 1. 模式判定（自动探测 + 分支确认）

触发后先探测目标模块状态，在分支点**向用户汇报确认**（用户一句话可纠正；也可用命令后缀显式指定跳过探测）：

| 探测事实 | 模式 | 流程 |
|---------|------|------|
| 模块文件夹存在 + 契约.md 存在 | 改造更新 | 按需求更新四件套 → 回写总契约索引 |
| 无文档 + 代码存在（glob 命中 Controller / views 页面） | 逆向提炼 | 读代码 → 提炼四件套草稿（标注置信度）→ 用户确认 → 回写索引 |
| 均不存在 | 文档先行 | 契约=需求分析：生成契约 + 接口骨架 → 用户确认（实施计划由 /module-plan 生成） |

**显式指定（可选，优先于探测）**：

- `/module-doc {模块名} 补文档` → 强制逆向提炼
- `/module-doc {模块名} 新建` → 强制文档先行
- `/module-doc {模块名} 改造` → 强制改造更新
- `/module-doc {模块名} 同步` → 按代码最新状态同步接口.md / 测试（契约语义变化走"改造"）

缺省走自动探测 + 分支确认。

## 2. 逆向提炼模式要点

1. 自动 glob 定位模块代码（`*Controller.java`、`views/*/{模块}/` 等模式，按档案目录约定）；
2. 读 Controller / Service / Mapper / 前端页；
3. 生成四件套**草稿**，逐项标注置信度：
   - 字段 / 状态机 / 接口 → "从代码推断"；
   - 权限语义 / 特殊约定 → "需人工确认"；
4. 用户确认修正后回写总契约索引。

## 3. 文档先行模式流程

1. 读项目档案（文档导航、标杆映射）→ 读总契约（依赖矩阵）；
2. 按档案标杆映射读标杆代码（映射缺失时 glob 找同类实现并提示回填档案）；
3. 涉及跨模块能力时读对应边界文档；
4. 生成契约（9 章，见模板规格）与接口骨架，图按绘图规范用 **mermaid** 绘制；
5. 用户确认（**实施计划由 /module-plan 按契约生成**）。

## 4. 生成文档的硬性要求

1. **导航区**：所有生成文档头部必须包含导航区（自动填值）：
   ```markdown
   > 关联文档：总契约.md、边界/{能力}边界.md、规范/后端开发规范.md
   > 关联代码：{标杆模块} → {代码路径}
   > 回链：本模块 接口.md / 测试.md（四件套互链）
   ```
2. **契约 §4 与接口.md 分工（防双维护）**：契约 §4 只保留"接口概览表 + 权限校验规则 + 接口对状态的影响"；字段级细节一律以 `接口.md` 为唯一事实源；
3. **绘图规范**：依赖图（§2）、状态机（§3）、页面结构（§5）一律 mermaid（flowchart / stateDiagram-v2），禁止 ASCII 图；
4. **文件名**：按档案"文档语言"映射（中文 `{文档根}/模块/{模块名}/契约.md` / 英文 `docs-framework/modules/{module}/contract.md`）；
5. **回写**：创建/更新模块后**回写总契约模块索引表**（模块名、模块文件夹、核心代码路径、标杆参考、边界依赖）。

## 5. 完成

输出文件清单 + 提示下一步：`/module-code {模块名}`（执行）或 `/module-review {模块名}`（验证）。
