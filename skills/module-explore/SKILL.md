# 探索与讨论技能（module-explore）

**当你不确定时，先探索再立项**（explore before propose）。AI 很容易"你问得含糊，它就自信地造出某个东西"——探索就是解药：一次零承诺的对话，把问题想清楚，等真正立项时，立的是对的项。

> **触发**：显式触发词为 `/module-explore {主题}`（仅英文技能名触发）；`{主题}` 用自然语言（如"订单导出"、"权限模型重构"）。

## 0. 应用路由（调研前先定位范围）

1. 读项目档案——**先读「应用清单」**（应用 → 类型/代码根/依赖），确定本主题**候选涉及的应用**；
2. 读总契约（应用拓扑、模块索引、跨模块业务流程 §六）与相关边界文档；
3. 按候选应用读其规范与标杆代码，调研现状（已有能力、可复用实现、相似模块、受影响的接口与消费方）；
4. **路由不确定时不要猜**——把"这次涉及哪些应用/哪个是主责服务"作为**待决策项**在对话中确认，而不是直接假定。

## 1. 探索姿态（stance，不是工作流）

**没有固定步骤、没有必备产出**——是思考伙伴，不是生成器：

- **好奇而非说教**：问题自然涌现，不按脚本审问；
- **一次一个聚焦问题**，并说明"这个问题解锁哪个决策"；用户要求批量时才批量；
- **先查证再提问**：能从代码/文档查到的事实不要问用户（不要让人重复系统里已有的事实）；
- **贴着代码探索**：相关现状、集成点、既有模式、隐藏复杂度都要实际读代码得出，不空谈；
- **多线展开**：抛多个方向让用户挑，不把对话硬拽向单一结论；
- **可视化**：用 mermaid 画结构/流程/方案对比，帮助把问题想清楚；
- **敢于推荐**：证据支持时给出首选方案与理由（含备选与权衡）；只涉及业务优先级/外部约束时让用户定；
- **对话即记录**：决策留在对话里（确认的决策 / 提议的缺省 / 未决问题分开），**默认不写文件**。

## 2. 硬护栏（红线，不可越）

1. **不写代码**：可以读文件、搜代码、跑只读命令；用户让你"顺手实现"时，提醒先退出探索、走 `/module-doc` → `/module-plan` → `/module-code`；
2. **不写契约、不写计划、不建模块文件夹、不改任何既有文档**；
3. **探索中的确认 ≠ 授权写文件**：任何写文件动作前，必须单独说明"要写哪个文件、写什么"，并等一个**独立的** yes/no；确认只覆盖你描述的这一次范围，扩大范围要重新确认；
4. **不复制契约内容**：探索记录只记"选项与理由"，业务语义真相永远在契约——论证只留一处（防双维护）；
5. **探索不是必经阶段**：需求已经明确时直接 `/module-doc {模块名} 新建`，不要为走流程而探索；
6. 与总契约 §六 业务流程分工：BF 是**已确定的流程真相**，探索是**未定的方案选项**，不重复绘制。

## 3. 产出与落盘

- **默认不落盘**：多数探索的价值在对话本身（决策、取舍、未决问题），说完即完成；
- **落盘触发**（满足其一，且需按 §2.3 单独确认）：
  - 用户显式要求：`/module-explore {主题} 落盘` 或"把结论记下来"；
  - 跨模块/跨应用重大决策，后续要作为契约的"为什么"被追溯；
- **落盘位置**：`{文档根}/探索/YYYY-MM-DD-{主题}.md`（全局目录，与 `计划/` 平级——跨应用主题多）；
- **模板**：`templates/探索/YYYY-MM-DD-{主题}.md.tpl`，四节——背景与问题 / 候选方案对比表 / 选定方案与理由 / **未决问题**；
- **定位**：探索记录是**单次决策记录**（同实施计划）：归档后不作规范依据，长期真相以事后生成的契约为准；探索记录**不参与** `doc-framework check` 硬校验（避免拖累初始化与存量项目）。

## 4. 交接（探索结束去哪）

| 探索结论 | 下一步 |
|----------|--------|
| 需求/方案已清晰，要立项 | `/module-doc {模块名} 新建`（契约 = 需求分析；生成后在契约导航区**回链探索记录**，回答"为什么这么设计"） |
| 是既有模块的改造 | `/module-doc {模块名} 改造`（先登记落点再实施） |
| 结论是"不做" | 记录结论与理由（如已落盘），结束，不产生任何文档变更 |
| 仅讨论、无产出 | 直接结束 |

> 探索记录**不能替代契约**：契约才是长期事实源；探索记录只是"当时为什么这么选"的决策快照。

## 5. 边界与协作

| 场景 | 流程 |
|------|------|
| 需求模糊 / 方案取舍 / 不熟代码库 / 范围存疑 | `/module-explore {主题}` → 想清楚 → `/module-doc 新建` |
| 需求明确 | 跳过探索，直接 `/module-doc 新建` |
| 探索中确认要做但涉及契约缺口 | 提示 `/module-doc 改造`（**落点先登记后实施**），探索本身不改契约 |
| 探索结论要落盘追溯 | `/module-explore {主题} 落盘` → `{文档根}/探索/...md` |

**分工**：探索与讨论归 `/module-explore`；契约文档归 `/module-doc`；计划归 `/module-plan`；代码归 `/module-code`；检查归 `/module-review`。
