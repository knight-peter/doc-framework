# 探索与讨论技能（module-explore）

**当你不确定时，先探索再立项**（explore before propose）。AI 很容易"你问得含糊，它就自信地造出某个东西"——探索就是解药：一次零承诺的对话，把问题想清楚，等真正立项时，立的是对的项。

> **触发**：显式触发词为 `/module-explore {主题}`（仅英文技能名触发）；`{主题}` 用自然语言（如"订单导出"、"权限模型重构"）。

## 0. 应用路由（调研前先定位范围）

0. **先扫探索记录**（防重复讨论）：跑 `doc-framework list --explore`（或列 `{文档根}/探索/` 与 `{文档根}/探索/归档/`）——同主题已有记录**先读再谈**：`已定案` 未吸收的看「结论去向」接着推进，不必重新讨论；`已作废` 的看 `已被` 行指向的新记录；
1. 读项目档案——**先读「应用清单」**（应用 → 类型/代码根/依赖），确定本主题**候选涉及的应用**；
2. 读总契约（应用拓扑 §3、模块索引 §4、跨模块业务流程 §6）与相关边界文档；
3. 按候选应用读其规范与标杆代码，调研现状（已有能力、可复用实现、相似模块、受影响的接口与消费方）；
4. **路由不确定时不要猜**——把"这次涉及哪些应用/哪个是主责服务"作为**待决策项**在对话中确认，而不是直接假定。

## 1. 探索姿态（stance，不是工作流）

**没有固定步骤、没有必备产出**——是思考伙伴，不是生成器：

- **好奇而非说教**：问题自然涌现，不按脚本审问；
- **一次一个聚焦问题**，并说明"这个问题解锁哪个决策"；用户要求批量时才批量；
- **先查证再提问**：能从代码/文档查到的事实不要问用户（不要让人重复系统里已有的事实）；
- **贴着代码探索**：相关现状、集成点、既有模式、隐藏复杂度都要实际读代码得出，不空谈；
- **多线展开**：抛多个方向让用户挑，不把对话硬拽向单一结论；
- **可视化**：用 mermaid 画结构/流程/方案对比，帮助把问题想清楚；
- **敢于推荐**：证据支持时给出首选方案与理由（含备选与权衡）；只涉及业务优先级/外部约束时让用户定；
- **对话即记录**：决策留在对话里（确认的决策 / 提议的缺省 / 未决问题分开），**默认不写文件**。

## 1′. 何时用 / 何时不用（判据先行，防仪式化）

### 处理哪五类不确定性

| 不确定什么 | explore 的产出可能是 |
|---|---|
| **要不要做** | 不做 / 用现有能力凑 / 值得做 |
| **做在哪** | 新建模块 / 扩展现有模块 / 只改配置或运维 |
| **做成什么样** | 方案 A vs B，各自代价与与现有契约的冲突点 |
| **范围多大** | 只做核心，还是连带影响 N 个模块/应用 |
| **现状是什么** | 这块代码原来怎么跑、有哪些既有模式可抄 |

一句话定位：**explore 用于"问题清楚、方案未定"**；已经清楚到"就是给订单加个导出"时，不需要 explore。

### 判据：决策的可逆成本 / 影响面（不是"不确定就探索"）

"需要想清楚"不等于"值得开一轮探索"——一行样式改动也需要想。真正该用 explore 的信号是**选错的返工代价**：

| 值得 explore | 不值得（直接 `/module-plan`） |
|---|---|
| 决策**难回退**：新建表 / 改状态机 / 定接口契约 | 改文案、调样式、加个字段展示 |
| **影响面大**：跨模块、跨应用、要动主责服务 | 单模块单文件 |
| **结论可能改变模型**：要不要新建模块 | 模型已定，只是实现 |
| 你不熟这块代码 | 标杆实现就在手边 |

**一句话判据**：**"选错了，返工要动契约 / 计划 / 多个模块吗？"** 要 → 先 explore；不要 → 直接 `/module-plan {模块名}`（存量增量 / 首次建模；纯实现小改走 `/module-code` 直改通道）。

### 为什么它不可替代：防模块膨胀的刹车 + 防仪式化

doc-framework 的整个模型是"模块契约"，天然倾向把什么都变成一个模块；只有 explore 能在源头说"这不用做"、"不需要新模块，扩展客户管理就行"、"这是运维问题，不是代码问题"。没有这个阀门，框架会不断产出**没人真正需要的模块契约**。同时禁止把"先探索一下"当成每个需求的必经关卡（那是把流式工具变成瀑布阶段）；若某段时间 explore 长期未被使用（如一个月 0 次），应重新评估它是否还值得作为独立技能存在。

## 2. 硬护栏（红线，不可越）

1. **不写代码**：可以读文件、搜代码、跑只读命令；用户让你"顺手实现"时，提醒先退出探索、走 `/module-plan` → `/module-code`（实施后由 `/module-doc` 合并落账）；
2. **不写契约、不写计划、不建模块文件夹、不改任何既有文档**；
3. **探索中的确认 ≠ 授权写文件**：任何写文件动作前，必须单独说明"要写哪个文件、写什么"，并等一个**独立的** yes/no；确认只覆盖你描述的这一次范围，扩大范围要重新确认；
4. **不复制契约内容**：探索记录只记"选项与理由"，业务语义真相永远在契约——论证只留一处（防双维护）；
5. **水位线纪律（不越过"契约细节"）**：本技能只谈 要不要做 / 放在哪 / 走哪条路 / 范围到哪 / 风险与冲突；**字段、状态机、接口、应用落点的具体设计属于计划的「语义增量」节**（不是 `/module-doc`，更不是本技能）。越线会让 explore 变成"第二份契约"，制造双维护漂移；
6. 与总契约 §6 业务流程分工：BF 是**已确定的流程真相**，探索是**未定的方案选项**，不重复绘制。

## 3. 产出与落盘

### 3.0 状态机（本技能是探索记录的唯一写手与状态机执行者）

| 状态 | 含义 | 位置 |
|------|------|------|
| **探索中** | 探索未完，中间结论先记下 | `探索/` |
| **已定案** | 结论已出、**待吸收**（等计划/文档来消费） | `探索/` |
| **已使用** | 结论已被计划/边界文档/契约消费 | `探索/归档/` |
| **已作废** | 结论被推翻/放弃（含被新记录取代） | `探索/归档/` |

流转规则：

- **探索中 → 已定案**：定案落盘时按**去向分流**——去向 ∈ {已立项, 已并入文档} 的留在 `探索/` **待消费**（根目录 = "待吸收结论"工作清单）；去向 = 维持"不做"/仅讨论的，**定案即移入 `探索/归档/`**（状态`已定案`，归档里照样止重复讨论）；
- **已定案 → 已使用**：由**消费方**执行（`/module-plan` 立项 / `/module-doc` 并入文档），见 §5——本技能不做；
- **已定案 / 已使用 → 已作废**：**被新探索推翻时由本技能执行**——新记录落盘时，同主题旧记录头部状态改 `已作废`、补 `> 已被：{新记录}（一句话原因）`；旧记录已在归档的**原地更新，不再移动**；
- `已作废` 的记录**可保留也可手动删除**（决策理由已随 `已被` 链传给新记录，删旧不丢链）。

### 3.1 何时落盘

- **默认不落盘**：多数探索说完即完成（价值在对话本身，见 §1「对话即记录」）；
- **强制落盘**：**待实现模块**（代码库零实现——无目录/路由/表/接口/契约）场景**必须落盘**——它是 explore → plan 的**唯一跨会话载体**，不落盘则 `/module-plan` 无从接手（仍按 §2 第 3 条单独确认写入）；
- **关键决策必填**（满足其一即**必须**落盘，不是"建议"）：
  - **存在被否方案**（做过候选对比、最终只选了一个）——**被否理由是探索记录的唯一内容，别处不留**：计划是单次决策记录（归档后不进任何清单、且可能被清理），契约只记当前真相（§9 只剩指针），所以"当初为什么不选 B"只在这里；
  - **跨模块 / 跨应用取舍**（改哪个模块的职责、语义放哪一侧）；
  - **否定性结论**（"不做 / 不必新建模块"）——三个月后同一需求会被重复讨论，落盘是唯一的止重复手段；
  - 若用户选择不落盘，**必须明确提示代价**："本决策的被否方案与理由不会留在任何地方（契约只记当前真相、§9 只剩指针；计划归档后不进清单、且可能被清理），未来可能重复讨论"——由用户确认放弃；
- **可选落盘**：用户显式要求（`/module-explore {主题} 落盘` 或"把结论记下来"）；其余日常探索的结论留在对话里即可。

### 3.2 怎么落盘

- **落盘位置**：`{文档根}/探索/YYYY-MM-DD-{主题}.md`；**定案即归档**（去向=不做/仅讨论）的直接写入 `{文档根}/探索/归档/`；
- **头部三行必填**（`list --explore` 据此聚合，缺了会显示"未知"）：`> 状态：`（四枚举）/ `> 结论去向：`（定案时填已知去向；消费后由消费方补实际路径）/ `> 已被：`（仅"已作废"且被取代时填，否则删除该行）；
- **模板**：`templates/探索/YYYY-MM-DD-{主题}.md.tpl`，五节——背景与问题 / 候选方案对比表 / 选定方案与理由 / **未决问题** / **待实现模块清单与关系**（待实现场景必填：拟新增模块、职责边界、与既有模块的调用/被调用关系、是否共享状态机或权限域）；
- **定位**：探索记录是**单次决策记录**，也是**决策档案的唯一长期归属**（"为什么这么做、为什么不那样"）——长期语义真相以契约为准，但**理由只在探索记录里**；探索记录**不参与** `doc-framework check` 硬校验（避免拖累初始化与存量项目），日常用 `doc-framework list --explore` 看全景。

## 4. 交接（探索结束去哪；编号出口）

| 探索结论 | 下一步 |
|----------|--------|
| **立项 · 存量模块变更**（有实现） | 输出**交接包**（见下）→ `/module-plan {模块名}`（完整计划：语义写进「语义增量」节）→ 实施后由 `/module-doc` 合并落账；可在契约导航区**回链探索记录**，回答"为什么这么设计" |
| **立项 · 待实现模块**（代码库零实现） | **强制落盘**探索记录（含「待实现模块清单与关系」节，状态`已定案`留 `探索/` 待消费）→ 交接包 → `/module-plan {模块名}` 首次建模计划 → 实施 → `/module-doc` create 分支建档——**首次建模全链路（判定式 + 各步职责）唯一权威见 /module-plan 协作表"待实现模块"行**；计划创建时该记录被消费、转`已使用`移入 `探索/归档/`（由 /module-plan 记账） |
| **立项（跨模块主题）** | **先逐模块 `/module-plan {模块名}` → 再 `/module-plan`（跨模块计划）**——「依据模块契约」可指向已存在的契约，或（被依赖方是待实现模块时）指向其首次建模计划路径 |
| 结论是"不做 / 不必新建模块" | 结束（零文档变更）；**建议落盘**（§3），并说明理由 |
| 结论是"无需文档变更" | 结束，说明理由，不产生任何文档变更 |
| 仅讨论、无产出 / 继续探索 | 直接结束，或继续探索 |

> **交接包六项**（选择立项时输出，与探索记录一致）：① **目标一句话**；② **模块清单与关系**；③ **范围与「不做」**；④ **选定方案与理由**；⑤ **留给 plan 的未决问题**；⑥ **能力归属与消费者**——只有“共享规则本身变化（协议/失败语义/安全红线）”才写 `边界/{能力}边界.md`；消费者接入不等于能力变更，先留在模块/应用规范。若确属能力变更，写清主责、受影响消费者、迁移、回滚。

## 5. 边界与协作（防重叠硬规则）

**分界线只有一条：模块是否已经确定。**

| | `/module-explore` | `/module-doc` |
|---|---|---|
| 对象 | 主题/问题（**可能还没有模块名**） | **已确定要做的模块**（且已有计划/代码） |
| 写权限 | 什么都不写（可选只落 `探索/`） | 写该模块契约与 接口.md（合并增量 / 代码对账 / 产物补齐） |
| 结论可能"不做"/"无需文档变更" | ✅ | "无需文档变更"✅（"不做"❌） |
| 多轮对话 | 有，且**无产物** | 有，且**每轮都是"按计划增量/代码事实落账"**（契约不承载未生效语义） |

两条硬规则（必须执行）：

1. **本技能**：模块名已明确、需求也清晰 → 直接 `/module-plan {模块名}`（该不该探索的判据见 §1′）；**不在 explore 做字段/接口级评审**；
2. **`/module-doc`**：用户给的是主题而非已确认模块名、且需求不成形 → **提示先 `/module-explore {主题}`**，不猜着写契约、不擅自建模块文件夹。

**消费记账权（/module-plan 与 /module-doc 的有界例外）**：两个技能对探索记录只有**机械记账**权限——按**先写后移**时序消费：先把自己文档里的引用写成**移动后的最终路径**（`探索/归档/YYYY-MM-DD-{主题}.md`），再翻状态（→`已使用`）、补写 `结论去向` 实际路径、移入 `探索/归档/`；**正文（选项/理由/被否原因）永不改写**。除此之外它们对探索记录只读。多消费者时首个消费者执行翻转+移动，后续消费者只追加第二条去向。

| 场景 | 流程 |
|------|------|
| 探索中确认要做、但发现契约缺口 | 提示把缺口写进计划的「语义增量」节（落点/接口皆由增量承载，实施后由合并增量落账）；**探索本身不改契约** |
| 探索结论要落盘追溯 | `/module-explore {主题} 落盘` → `{文档根}/探索/…md`（待实现模块场景强制落盘；落盘判定见 §3.1） |
