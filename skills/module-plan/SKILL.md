# 实施计划技能（module-plan）

负责实施计划的**创建 / 修订 / 状态流转**。与 /module-doc、/module-code 分工：**契约归 /module-doc、计划归 /module-plan、代码归 /module-code**，/module-review 兜底校验一致性。

> **触发**：显式触发词为 `/module-plan`（仅英文技能名触发）。

## 计划落盘位置

- **单模块计划**（默认）：`{文档根}/模块/{模块名}/计划/YYYY-MM-DD-{主题}.md` —— 路径含模块名，定位零歧义；
- **跨模块计划**（引用多个契约）：`{文档根}/计划/YYYY-MM-DD-{主题}.md` —— 全局目录专放跨模块主题。

文件名必须带日期前缀（便于归档）；一契约可对应多份计划，按 **日期+主题** 区分。

## 0. 定位目标计划（三级，按精度优先）

| 触发 | 定位方式 |
|------|----------|
| `/module-plan {计划路径}` | 路径直达（绝对或相对路径，相对以项目根为基准） |
| `/module-plan {模块名} {YYYY-MM-DD-主题}` | 日期+主题精确匹配 `模块/{模块名}/计划/` 下文件名 |
| `/module-plan {模块名}` | glob `模块/{模块名}/计划/*.md` 列出清单供选择；无匹配则进入"新建" |

只给模块名时，清单按 **编号 | 日期-主题 | 状态 | 修订版本** 列出（例：`1. 2025-09-01 用户登录改造 [待审核] v2`），用户回复编号即定位。

## 1. 读上下文（创建时）

1. 读项目档案（目录约定、分层）；
2. 读 `{文档根}/模块/{模块名}/` 四件套——契约 = 约束（§3 数据模型 / §4 接口概览）、接口.md 字段细节；
3. 涉及跨模块能力时读对应边界文档。

## 2. 创建 / 修订

### 新建

按模板 `templates/计划/YYYY-MM-DD-{实施主题}.md.tpl` 渲染（状态=待审核，修订记录 v1），必备章节：需求理解 / 变更文件清单（SQL/后端/前端逐个列出）/ 关键设计决策 / 验收标准 / 待确认事项 / 里程碑 / **回写清单**。向用户汇报并等待确认。

### 修订

1. 加载目标计划（按 §0 定位）；
2. 展示当前 **状态 + 待确认事项 + 修订记录**，用户给出修改意见；
3. 编辑正文 → **修订记录追加一行**（版本+1、日期、状态、修改点、评审结论）——追加式，不覆盖历史；
4. 状态流转（红线）：
   - 「已批准」→ 必须先退回「修订中」→ 修订 → 「待审核」重新评审（**不允许直接修改已批准计划**）；
   - 「待审核 / 修订中」→ 修订完 → 「待审核」；
   - 否决 / 放弃 → 「已废弃」（终态，注明原因）。

## 3. 状态约定

- 状态枚举：`待审核 / 修订中 / 已批准 / 实施中 / 已完成 / 已废弃`；
- 状态是**事实登记**：AI 登记、用户确认流转；评审可在文档内或文档外进行，状态如实记录即可，不强制流程；
- 实施类状态（实施中 / 已完成）由 /module-code 实施时登记，本技能不登记。

## 4. 边界

- 计划评审中发现契约缺口 → 提示 `/module-doc {模块名} 改造`，不得绕过契约直接改计划；
- 归档后的计划**不作规范依据**，长期看契约"变更记录"章节；
- 本技能不实施代码、不回写契约变更记录（归 /module-code）。

## 与 /module-doc、/module-code 的协作约定

| 场景 | 流程 |
|------|------|
| 正向开发 | `/module-doc 新建`（契约先行）→ `/module-plan`（创建计划）→ `/module-code {计划路径}`（实施+回写）→ `/module-doc 同步`（收尾） |
| 改造 | `/module-doc 改造`（更新契约）→ `/module-plan`（新计划或修订）→ `/module-code`（实施+回写） |
| 计划未批准 | `/module-code` 拒绝执行 → 提示 `/module-plan` 处理（修订或废弃） |

/module-review 兜底校验文档与代码一致性（含回写查账）。
