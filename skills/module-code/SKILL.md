# 模块代码技能（module-code）

负责**执行实施计划**——**以实施计划为主、契约为约束、白名单为边界**，不创建/修改四件套文档（文档归 /module-doc）、不创建/修订计划（计划归 /module-plan）。

> **触发**：显式触发词为 `/module-code`（仅英文技能名触发）。

## 0. 定位实施计划（二选一）

| 触发 | 定位方式 |
|------|----------|
| `/module-code {计划路径}` | 路径直达（主推，绝对或相对路径，相对以项目根为基准）；模块名从路径 `模块/{模块名}/计划/` 或计划文档「依据模块契约」行解析 |
| `/module-code {模块名}` | 兜底：glob `模块/{模块名}/计划/*.md`，**仅列出「已批准」计划**供选择 |

**红线**：只执行「已批准」状态的计划；「待审核 / 修订中 / 已废弃」一律拒绝执行，提示先用 `/module-plan` 处理。

## 1. 加载计划与上下文

1. 加载实施计划文件，校验状态=已批准；读取**逐应用表态**、变更文件清单、实施顺序、关键设计决策、接口兼容性声明、验收标准、回写清单；
2. 解析模块名（传路径时），读模块四件套——契约 = 约束（§3 数据模型 / §4 接口概览 / §5 应用落点）、接口.md 字段细节（服务端真相）；
3. 读项目档案「应用清单」——**只加载表态「改动」的应用**的规范（`规范/应用-{应用标识}.md`）与标杆代码（可见性 ≠ 上下文）；映射缺失时 glob 找同类实现并提示回填档案；
4. 涉及跨模块/跨服务能力时读对应边界文档。

## 2. 路径白名单（执行边界，每次写文件前自检）

**白名单 = 表态「改动」应用的代码根 ∪ 且 ∈ 计划变更文件清单**（档案应用清单提供代码根前缀；代码根互相嵌套时按最长前缀优先归属）。

- 每次 edit/write 前：目标路径必须在白名单内——**越界即停**，不偷偷改；
- 确需改动白名单外的文件（如契约缺口：接口没覆盖、落点未登记）→ 走纠偏回路：停下 → 定性（代码 Bug vs 契约缺口）→ 提示 `/module-plan 修订`（已批准 → 退回修订中 → 补表态/补清单 → 重新批准）或 `/module-doc 改造` → 批准后白名单更新再继续；
- 边界情况：某应用代码根为 `./` 时前缀约束失效，退化为**纯文件级清单**（只允许动清单逐条列出的文件，宁严勿宽）。

## 3. 按依赖序实施

按计划「实施顺序」节执行（缺省时按默认依赖序）：

1. SQL（进对应服务的 `{代码根}/sql/change/` 目录）；
2. **主责服务**——接口.md 先定稿（**接口契约先行**），数据模型、API、状态机、特殊约定必须遵守契约；
3. 下游/聚合服务——对着已定稿的接口.md 实现转发/聚合，禁止倒推；
4. 逐端实施——每端完成后**独立自检**再进入下一端；
5. **契约作约束**：偏离时先改契约（/module-doc 改造）再实施，不得绕过契约直接改代码。

## 4. 一致性自检

对照检查：代码 ↔ 实施计划 ↔ 契约 §4 / 接口.md。

- 发现偏差（路径/字段/权限标识）→ 列出"待同步项"并提示 `/module-doc {模块名} 同步`；
- 契约语义/权限层面变化（状态机新增状态、权限标识变更）→ 提示 `/module-doc {模块名} 改造`；
- 状态机/权限标识在各应用间必须一致（跨应用不变量）——发现某端自定义语义，按契约纠正。

## 5. 回写（交付义务，不可跳过）

按实施计划"回写清单"逐项登记：

- 契约变更记录追加一行（**事实登记**：改了哪些字段/接口/状态机）；
- 含需生产执行的 SQL 时，契约 §10 生产环境 SQL 执行登记追加一行（**所属服务** + 文件引用 + 影响摘要，状态=待执行；不复制 SQL 正文）；
- **接口.md §5 各应用接入状态更新**（本次实施的应用打勾）；
- 契约 §5 应用落点表同步（新增落点/差异说明变化时提示 /module-doc）；
- 测试执行记录；
- 实施计划状态登记为「已完成」（**事实登记**，状态归 /module-plan 的约定，本技能只登记实施类状态）；
- 提示 `/module-doc 同步`（同步接口.md 并更新总契约索引——**索引由 /module-doc 维护**）。

**边界**：/module-code 只做事实登记；契约语义/权限层面的修改归 /module-doc，计划创建/修订归 /module-plan，提示后等确认，不得自行改动。

## 与 /module-doc、/module-plan 的协作约定

| 场景 | 流程 |
|------|------|
| 正向开发 | `/module-doc 新建`（契约先行）→ `/module-plan`（创建计划）→ `/module-code`（实施+回写）→ `/module-doc 同步`（收尾） |
| 改造 | `/module-doc 改造`（更新契约）→ `/module-plan`（新计划）→ `/module-code`（实施+回写） |
| 计划未批准 | `/module-code` 拒绝执行 → 提示 `/module-plan` 处理 |
| 白名单外需求 | 停下 → `/module-plan 修订` 或 `/module-doc 改造` → 重新批准后继续 |

/module-review 兜底校验文档与代码一致性（多应用对账 + git diff 对账 + 回写查账）。
